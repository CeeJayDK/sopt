GPU Blueprint / OpBench

OpBench

What GPU instructions cost on your graphics card.

How to run

From the GPU Blueprint menu (GPU-Blueprint.bat): 1 to 3 run it with the other programs, 4 alone. It takes a few minutes and writes Reports\opbench-<GPU>.csv.

Laptops with two graphics cards: OpBench asks the NVIDIA / AMD driver for the fast card. On older AMD laptops, set OpBench.exe to "High Performance" in the Switchable Graphics settings if it still runs on the built-in graphics. Windows may keep showing the built-in card's name even then.

Command line

--listshow the graphics cards Windows reports, with their numbers
--adapter Nmeasure card number N instead of the one with the most video memory
--filter textonly tests whose name contains text (quick checks)

Why

sopt rewrites small pieces of shader math into cheaper forms that give the same result. Which form is cheaper depends on the GPU. A sign() costs one instruction on one card and seven on another, and some cards apply saturate() or * 2 for free. OpBench measures these costs on real cards. The results become sopt's cost models, one per GPU family (for example NVIDIA Turing, NVIDIA Blackwell, AMD RDNA, Intel Gen9).

How a test works

Each test is one small step, repeated thousands of times in a chain inside a compute shader (Direct3D 11):

x = mad(f(x), c.x, c.y)

f is the operation under test, and the mad (multiply-add) keeps x in a sane range. The constants c change at every step, so neither Microsoft's shader compiler nor the GPU driver can fold the chain away. The shader code of every test, with fxc's DXBC output, is written to Reports\Shaders\OpBench\ so folded tests can be spotted.

The reference test is the bare step x = mad(x, c.x, c.y): one fma (fused multiply-add) per step. Every time is divided by the reference's time and multiplied by 4, so one fma = 4 units. A test's cost is its time minus the time of its base test. The base is the same step without the operation under test, usually the reference itself. So "Cost 4" means the operation costs as much as one more fma, and "Cost 0" means it is free (the GPU folds it into a neighbouring instruction).

Before every test the reference is measured again. A GPU clock change (boost, temperature, power saving) then affects the reference and the test alike, instead of making the test look cheaper or dearer. Every test runs twice: forward through its section, then backward, so slow drift cancels out. When the two readings of a test disagree (by more than 0.75 units or 15%), it is measured again, like a third sensor: two readings show that one is wrong, three or more show which one. This repeats until more than half of the readings agree (at most 6 passes); the result is the mean of the agreeing readings. A test without such a majority is marked "no consensus".

Three ways of running

Cost, many in parallel tput8 independent chains per thread, about a million threads: what an instruction costs when the GPU is fully busy, as in a game. This is the number sopt uses, and the summary shows it.
Cost, one dependent chain dep1 chain per thread, about a million threads. Every step waits for the one before it, and the GPU hides the waiting by switching between threads.
Latency, one at a time lat1 chain, one group of 64 threads. How long one step takes until its result is ready, since nothing can hide the wait.

All three are in the CSV (its codes tput, dep, lat). Every number is a cost: lower is better.

The tests

Modifiers and folds

Often free: the GPU applies them inside another instruction.

neg, abs, negabs-x, abs(x), -abs(x) feeding the mad: source modifiers, usually free.
saturateclamp to [0, 1] on the previous mad's result: an output modifier.
satmadsaturate(mad(...)): the same, measured against two mads.
mulx * c before the mad: some drivers merge it into the mad.
omod2, omodhalfrcp(x) * 2 and * 0.5: AMD can scale a result by 2, 4 or 0.5 for free.
omod4rcp(x) * 4: AMD's third output modifier scale.
omod8, omod0.25, omod0.125rcp(x) * 8, * 0.25, * 0.125: scales that DX9-era GPUs applied for free (_x8, _d4, _d8). Expected to cost a multiply on current GPUs: measured to know.
omod3rcp(x) * 3: the control (3 is no output modifier scale).

Basic arithmetic

min, max, stepmin / max / compare; NVIDIA Turing runs one of them beside an fma.
add, subone add.
fma1mad(x, x, c): one fma with a single constant. On AMD GCN the reference's two constants cost a second instruction, so this is the true fp32 rate there (the score uses whichever is faster).
mad2, contracta second mad, and x * a + b written out (compiled to one fma?).
max3, minmaxmax(max()), min(max()): AMD has 3-operand instructions for these.
clampclamp(x, a, b): AMD v_med3 does it in one instruction, others need two.
selectx < a ? b : x: compare + select.
lerplerp(a, x, t): fxc writes it as add + mad.

Rounding and sign

floor, ceil, round, trunc, fracthe rounding instructions (quarter rate on some NVIDIA cards). trunc drops the fraction (round toward zero) instead of rounding by sign.
roundadd, flooradd, fracaddround / floor / frac built from adds with a magic constant (1.5 × 223), for cards where the rounding instructions are slow.
signHLSL sign(): fxc writes compare, compare, int subtract, int → float.
signsel2, signbits, signsat, signmad, signclamp, signselother ways to get -1 / 0 / +1 (signsel2 and signbits give +1 at 0; signbits copies the sign bit onto 1.0 with two integer instructions), without the int → float conversion that makes sign() slow on newer NVIDIA cards.

Division and transcendentals

rcp, rsqrt, sqrt, exp2, log2, sin, costhe special-function unit (1/4 or 1/8 rate on most cards).
div, divxyc / x and x / y (rcp + mul).
exp, logfxc: exp2 / log2 with a multiply.
powfxc: log2, mul, exp2.
rcpmaxmax(rcp(x), c): the base for the omod tests.

Vector (float2 / float3 / float4)

mad2v, mad3v, mad4vthe reference on 2, 3 and 4 components (2, 3, 4 fmas).
dot2, dot3, dot4dot products. fxc writes one dp2 / dp3 / dp4 instruction, but GPUs since about 2010 have no such instruction: the driver splits it into mul + fmas. These show whether that is so (old VLIW cards did have a real dot).
crosscross product: 3 mul + 3 fma.
length, distancedot, sqrt (distance: 3 subtracts first), plus one fma of the step.
normalizedot, rsqrt and 3 multiplies.
reflecti - 2 * dot(i, n) * n.
refract, faceforwardrefraction (dot, sqrt, select) and faceforward (dot, compare, select).
det3determinant of a float3x3.
matmul4mul(float4x4, float4): 4 dot products (16 fmas).
transposethe same with transpose(): should cost nothing extra.

Integer and conversions

Chains of uint values, x = (x ^ a) * b, with random 32-bit constants.

bitorone integer OR on a float value: is switching between float and int free?
ixmulthe integer base step: xor + 32-bit multiply.
iadd, iand, iminone more add / and / unsigned min (NVIDIA can merge and + xor into one LOP3).
ishrx ^ (x >> 13): shift + xor.
irotrotate by 7: shl, shr, or, or one funnel shift / align instruction.
imula second 32-bit multiply (slower than float on some cards).
popc, fbhcountbits, firstbithigh.
bitrevreversebits.
fblfirstbitlow.
icmpselunsigned compare and select.
unitfuint → float in [1, 2) through the bits (shift, or): a fast random-number trick.
utof, ftou, itofuint → float and float → uint conversions; int → float.
ftoitoffloat → int, an integer or, int → float (fxc writes float(int(x)) alone as one truncation instruction, so the or keeps the conversions).
udiv, umod, idiv, imodunsigned / signed divide and modulo by a small divisor (1 .. 255). Most GPUs have no integer divide instruction, so the driver writes a sequence; signed is longer.

Half precision (min16float)

mad16, add16, mul16, rcp16, sqrt16, exp2_16the same steps in 16-bit floats. AMD RDNA and some other cards run these at twice the rate (two per instruction). Drivers may run min16float at 32 bits instead. The summary and the CSV header say which.

Compute: groupshared memory and barriers

gsread, gswrite, gswritereadgroupshared memory (fast on-chip memory shared by a thread group).
gsread32, gswrite32lanes 32 words apart: they hit the same memory bank (bank conflicts).
barrier, groupbarrier, membarrierbarrier() / groupMemoryBarrier() / memoryBarrier() after a write.

Compute: groupshared atomics

aAdd, aAnd, aOr, aXor, aMin, aMax, aXchg, aCmpXchgatomicAdd ... atomicCompareExchange, each thread on its own address; with "1" (aAdd1 ...): the group's 64 threads on one address.

Compute: local arrays and branches

arrayread, arraywritea local float A[16] indexed at run time (the index differs per thread). fxc puts such arrays in indexable temps, which some GPUs keep in slow memory.
constarraya static const float K[16] indexed at run time.
selectboth4 sin and 4 cos both computed, one result picked.
branchunithe same as a branch; all threads of a group take the same side.
branchdivthe same as a branch; neighbouring threads take different sides, so every group runs both.

Parallel issue: an fma and X together

fma+int, fma+minmax, fma+cvt, fma+rcp, fma+halfhalf of the chains run mad, the other half run X (integer xor + add, min + max, uint → float, rcp, an fp16 fma); int1 ... half1 measure X alone. Cost = one fma and one X together; the comment gives it as a percentage of the two one after the other (4 + X alone). Below ~85% they run at the same time: separate units or slots (old AMD VLIW cards, NVIDIA's integer pipe beside the float pipe, a second FP32 pipe, AMD dual issue).
fma+fmacontrol: the same fma on both halves (should be ~100%).

Reading the CSV

Lines starting with # describe the card, driver, OpBench version and how much the reference moved (drift) in each mode. Then one row per mode and test:

unitsthe test's time in units (4 = one fma): the mean of its agreeing readings
units_vs_baseminus its base test: the cost shown in the summary
vs_base_fwd, vs_base_bwdthe same for the forward and the backward pass alone
passes, consensus, readingshow many passes the test needed, whether most readings agreed, and every reading (units, ';'-separated)
step, notethe HLSL step, and what it is about
expectedwhat other cards of the same family measured (tput only, see below)

The CSV is written again after every section, so a run stopped early still leaves its results.

Compared with other cards

OpBench knows what the cards measured so far cost in each test, per family (architecture: Turing, RDNA 2, Gen9 ...): the median over the family's cards, one report each. A test where your card is more than 25% (and more than 1.5 units) away from that is marked usually N in its section, and the end of the run lists them. Such differences are what make a report especially interesting: a new driver doing something better, a card that belongs in a family of its own, or a run whose clock moved. A card from a family nobody has measured yet says so. The CSV has the family in a # line, the differences in another and the expected cost per test in the expected column. The table is built into OpBench and grows with every release as reports come in.

The score

fp32TFLOPS from the reference multiply-add or fma1, whichever is faster (2 floating point operations each).
fp16 (min16float)TFLOPS of the half precision multiply-add ("runs at fp32" when the driver does not run min16float at 16 bits).
Special functionsrcp per second (Gops/s); sqrt, exp2, sin and the like usually run at the same rate.

The fp32 number is the one GPU spec lists give ("processing power"); measured ones are usually a bit lower, or higher when the GPU boosts above its listed clock.
