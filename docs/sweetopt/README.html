SweetOpt

The super sweet shader optimizer: finds faster ways to write the math in ReShade shaders, checks every one, and lets you choose.

SweetOpt looks for cheaper ways to write the arithmetic in ReShade FX, plain HLSL and GLSL shaders. Every rewrite it offers is checked to give the same result as the original, within what the output can show (an 8-bit back buffer hides small differences). In easy mode (the default in the menu) it writes ready files with the changes we recommend put in; in expert mode every variant is written next to the original behind a preprocessor switch, so you can compare them in ReShade and choose.

This is an early release: feedback is very welcome (see the end).

1. Run it on your shaders

Windows, the easy way: double-click SweetOpt.bat. A menu opens:

KeyWhat it does
1Choose your reshade-shaders\Shaders folder, to optimize every effect in it. Not needed when you pick a folder or an effect with 2: SweetOpt finds ReShade.fxh by itself.
2Choose what to optimize: everything, one folder (such as SweetFX), one effect, or a GLSL / HLSL shader file that is not a ReShade effect (then no Shaders folder is needed).
3The time per statement: 5, 20 or 60 seconds (more time can find more).
4Your graphics card family (what counts as faster). Variants are never slower on it, but every variant is also costed for the other families, and changes that help them are kept too. It then asks whether to search with the other families' costs as well (finds more of those; about 4x the time).
MThe mode. Easy: ready files with our recommended changes put in, nothing to choose; it then asks whether to keep a switch for each change (so single changes can be turned off again). Expert: every variant behind a switch with its cost and accuracy.
EEasy mode settings, safe by default: whether easy mode may use "too exact" variants (no), and which bigger rewrites it makes (tables and vertex shader moves; or all, blends to the blend stage too; or none).
5Start.
6Quick look: which statements SweetOpt would work on (seconds, no search).
7Open the results (the sopt-out folder and sopt-report.md).
8Edit value ranges (see 4).
9Open this page.

The menu remembers your choices. All CPU cores are used.

From a command prompt, the programs are in the bin folder: point sopt-fx at an effect file or a folder of effects, with -I for the folder that holds ReShade.fxh:

Windows:  bin\sopt-fx -I "C:\Games\MyGame\reshade-shaders\Shaders" -o out "C:\Games\MyGame\reshade-shaders\Shaders\SweetFX"
Linux:    bin/sopt-fx -I ~/reshade-shaders/Shaders -o out ~/reshade-shaders/Shaders/SweetFX

It searches every arithmetic statement, 5 seconds each by default (--time 20 for more; --bits also tries bit tricks with asuint / asfloat, slower). Plain HLSL works too: .hlsl / .hlsli files are read as SM5 pixel shaders, or compute shaders when the entry point has [numthreads] (--entry NAME, default main). GLSL fragment shaders (.frag, .fs, .glsl, or --glsl) are read too, and their variants are written in GLSL after the #version line.

Easy mode from the command line: --easy (ready files, no switches) or --easy-switches (switches set to our picks); --easy-too-exact also allows "too exact" variants, --easy-rewrites none|safe|all chooses the bigger rewrites (default safe). Easy mode picks, per statement, the fastest variant that is bit-exact or within budget, has no problem inputs and is slower on no measured graphics card; the report still lists everything.

Other graphics cards: every variant is costed for each GPU family SweetOpt has a cost model for (AMD GCN, RDNA 2 / 3 / 4, NVIDIA Maxwell to Blackwell, Intel Gen7.5 / 9 / 12), and the report shows a table per statement with the change on each family, where it helps and where it harms. A variant that is as fast as the original on your card but faster on other families is kept ("faster on other GPUs"). When such a variant is faster on some families and slower on others, easy mode weighs them by how many Steam users own each family (Steam Hardware & Software Survey, read when a version is released) and takes it only when it helps more than it harms; in expert mode you choose. --all-platforms also searches with the AMD RDNA 3, NVIDIA Turing, NVIDIA Ampere and Intel Gen9 costs, which finds more such variants (about 4x the search time). At the end SweetOpt sums up what the changes save, on your card and on the others.

2. Read the results

FileWhat
sopt-report.mdevery statement with cheaper variants: the original, each variant, its cost, its accuracy class and its error (any Markdown viewer or a text editor)
*.fx / *.fxhthe faster copies of the changed files, in the same folders as the originals (for example SweetFX\Vibrance.fx). In easy mode the changes are written in; with switches, each changed statement is written as #if SOPT_<file>_<line> == 1 … variant 1 … #else … the original … #endif
sopt-facts.txtinputs whose value range SweetOpt could not work out (see 4)
sopt-cache.txtthis run's results for the next run in the same folder: unchanged statements are not searched again, changed ones (new value ranges, another card) start from the earlier finds; delete it or use --no-cache to start from scratch
sopt-found.txtevery rewrite found, as rules (material for SweetOpt's rewrite library)

Accuracy classes: bit-exact, 8-bit identical, within budget, too exact (closer to exact math than the original: differs from it only where the original rounds), less accurate (listed with its error so you can judge it).

Scheduling: for statements that read uniforms or textures, the report also shows the cost with ReShade's performance mode on (uniforms become constants, so math on them alone is free) and the tail, the work left once the last texture sample arrives. SweetOpt groups math on constants and uniforms together and lets the last sample enter last; variants that are not faster but faster in performance mode, or that have a shorter tail, are listed as faster in performance mode / better scheduling (not faster). --perf-mode-first makes the performance mode cost the main one, --no-schedule turns this off.

3. Use the results in ReShade

  1. Make a backup of your game's reshade-shaders\Shaders folder (copy it somewhere else).
  2. Copy everything in sopt-out into your Shaders folder and choose Replace. The folders inside sopt-out match the ones in Shaders, so every file lands on the original it replaces. (The sopt-… text files are SweetOpt's report; ReShade ignores them, you can leave them out.)
  3. Start the game. In easy mode (the menu's default) that is all: the faster code is already in the files.

Do not add sopt-out to ReShade's effect search paths instead: ReShade would then load every effect twice, the original and the copy. To undo, put the backup back.

The SOPT_ switches

Files made in expert mode, or in easy mode with switches, keep the original code next to each change. Preprocessor definitions choose which runs; ReShade lists them under the effect (or set them globally in its settings):

SOPT_GROUPthe choice for every changed statement at once: 0 = the original code everywhere, 1 = variant 1 everywhere, 2 = variant 2 … (the last variant where a statement has fewer). Expert mode starts at 0, easy mode with switches at 1 (our picks).
SOPT_<file>_<line>one changed statement on its own (0 = the original), overriding SOPT_GROUP for it.
SOPT_TOO_EXACT = 0turns off the "too exact" variants (in case an effect relies on rounding)
SOPT_AUTO = 1per GPU vendor, the variant measured fastest (only in files made with --isa / --sass, which need extra tools)

SOPT_GROUP is there to test quickly: step it through 0, 1, 2 … and compare the image (SweetFX's Compare.fx helps) and the performance statistics. If one number changes the picture or breaks the effect, set SOPT_GROUP back to 0 and turn the SOPT_<file>_<line> switches on one at a time to find the statement and variant behind it; sopt-report.md shows what each one does. Please tell us about it, so SweetOpt can learn from it.

4. Better results with value ranges (optional)

A shortcut is often only correct for some values: x * x instead of pow(x, 2.0) is fine for any x, but others hold only when x stays between 0 and 1. SweetOpt works out what values an input can have where it can (a setting's ui_min / ui_max, a texture's format, a texture coordinate, a color, …), and only uses such shortcuts when it knows. The results then say that some shortcuts "need value ranges".

You can tell it the rest. Press 8 in the menu: sopt-facts.txt opens with one line per input it could not work out, for example

# Vibrance.fx VibrancePass luma = [-1000, 1000]   # no guess (the default); 1 region

If you know the value's range, remove the # at the start and put the real range in, for example Vibrance.fx VibrancePass luma = [0, 1]. Save, and press 5 to run again: SweetOpt uses those ranges and can then use more shortcuts. Only give ranges you are sure of: a wrong range can give a wrong picture. From the command line: --facts sopt-facts.txt (or --ask to answer interactively).

5. Single expressions: sopt

sopt optimizes one expression described in a small text file, e.g. screen.sopt:

input a : float in [0, 1] grid 255
input b : float in [0, 1] grid 255
output r = 1.0 - (1.0 - a) * (1.0 - b)
budget r : color8

bin\sopt screen.sopt lists the cheaper forms it found and verified. --help lists the options of both programs (cost models for other GPUs: --cost-model amd-rdna2, nvidia-turing, intel-gen9, …).

bin\sopt-fxc.exe is Microsoft's shader compiler (the one ReShade uses for Direct3D 10-12) for sopt-fx --backends, which finds it next to itself: the report then shows each variant's DXBC instruction count and whether fxc already makes the same code.

Requirements

  • Windows 10 or 11 (x64) with the Microsoft Visual C++ 2015-2022 redistributable, which almost every gaming PC already has: vc_redist.x64.exe. Or Linux x64.

The programs are not code-signed yet, so Windows Defender or SmartScreen may warn about them. The download page lists their SHA-256 checksums.
