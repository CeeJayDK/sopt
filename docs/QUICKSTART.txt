sopt - shader superoptimizer: quick start
=========================================

sopt looks for cheaper ways to write the arithmetic in ReShade FX (and plain HLSL) pixel
shaders. Every rewrite it offers is checked to give the same result as the original, within
what the output can show (an 8-bit back buffer hides small differences), and it is written next
to the original behind a preprocessor switch, so you can compare them in ReShade and choose.

This is an early release: feedback is very welcome (see the end).


1. Run sopt-fx on your shaders
------------------------------
Windows, the easy way: double-click sopt-menu.bat. Press 1 to choose your reshade-shaders\Shaders
folder (the one with ReShade.fxh), 2 to choose what to optimize (everything, one folder such as
SweetFX, or one effect), then 5 to start. 7 opens the results. The menu remembers your choices
(sopt-menu.ini).

Or from a command prompt in this folder: point sopt-fx at an effect file or a folder of effects,
with -I for the folder that holds ReShade.fxh:

  Windows:
    sopt-fx -I "C:\Games\MyGame\reshade-shaders\Shaders" -o out "C:\Games\MyGame\reshade-shaders\Shaders\SweetFX"

  Linux:
    ./sopt-fx -I ~/reshade-shaders/Shaders -o out ~/reshade-shaders/Shaders/SweetFX

It searches every arithmetic statement of the pixel and compute shaders, 5 seconds each by
default (more time can find more: --time 20). All CPU cores are used.

Plain HLSL works too: .hlsl / .hlsli files are read as SM5 pixel shaders, or compute shaders
when the entry point has [numthreads] (--entry NAME for the entry point, default main).


2. Read the results (folder "out")
----------------------------------
  sopt-report.md   every statement with cheaper variants: the original, each variant, its cost,
                   its accuracy class and its error. Open it in any Markdown viewer (or a text
                   editor).
  *.fx / *.fxh     copies of the changed files, each changed statement written as
                     #if SOPT_<file>_<line> == 1
                         ... variant 1 ...
                     #else
                         ... the original ...
                     #endif
  sopt-facts.txt   inputs whose value range sopt could not work out (see 4.)
  sopt-found.txt   every rewrite found, as rules (material for sopt's rewrite library)

Accuracy classes: bit-exact, 8-bit identical, within budget, too exact (closer to exact math
than the original: differs from it only where the original rounds), less accurate (listed with
its error so you can judge it).


3. Try the variants in ReShade
------------------------------
Use a copy of your game's reshade-shaders folder (or point ReShade's effect search path at the
"out" folder first), so the originals stay untouched. Then set preprocessor definitions in
ReShade's UI:

  SOPT_ALL = 1          variant 1 of every statement (2, 3: the next ones)
  SOPT_<file>_<line>    one statement on its own (0 = the original)
  SOPT_TOO_EXACT = 0    turns off the "too exact" variants (in case an effect relies on rounding)
  SOPT_AUTO = 1         per GPU vendor, the variant measured fastest (only in files made with
                        --isa / --sass, which need extra tools)

Compare the image with SOPT_ALL = 0 and 1 (SweetFX's Compare.fx helps), and look at the
performance statistics.


4. Better results with value ranges (optional)
----------------------------------------------
sopt only rewrites a statement when it knows the range of every input (from ui_min / ui_max,
texture formats, texture coordinates, ...). Inputs it could not work out are listed in
out/sopt-facts.txt with a suggested range. Uncomment and correct the lines you know, then run
again with --facts out/sopt-facts.txt (or answer the questions interactively with --ask). In
sopt-menu.bat: press 8, edit the file Notepad opens, save, and start again.


5. The sopt tool (single expressions)
-------------------------------------
sopt optimizes one expression described in a small text file, e.g. screen.sopt:

  input a : float in [0, 1] grid 255
  input b : float in [0, 1] grid 255
  output r = 1.0 - (1.0 - a) * (1.0 - b)
  budget r : color8

  sopt screen.sopt

It lists the cheaper forms it found and verified. --help lists the options of both tools
(cost models for other GPUs: --cost-model amd-rdna2, nvidia-turing, intel-gen9, ...).
